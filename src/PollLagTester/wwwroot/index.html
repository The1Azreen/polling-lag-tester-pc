What's measured, and how

Polling rate comes from Windows Raw Input, registered with RIDEV_INPUTSINK so it keeps working while your game has focus. Every report gets a QPC timestamp on a dedicated high-priority thread the moment it arrives. The rate comes from the gaps between reports from the same device.

  • Mouse: reports only while moving. Move fast, in circles. Avg includes slow-movement gaps; median and nominal show the configured rate. On-cadence = reports within ±15% of the nominal interval; off-cadence = gaps over 1.5× (skipped polls or slow movement). Jitter = σ of intervals around nominal.
  • Keyboard: reports only when a key changes, so a normal average is meaningless. Each event still lands on a USB poll, so the gaps snap to multiples of the poll period. The estimator finds that grid. Roll your fingers across many keys quickly. Rates above 1-2 kHz may not be resolvable because of OS timing jitter.
  • Controller: any HID gamepad (DualSense/DS4, Xbox "HID-compliant game controller", Switch Pro, 8BitDo…). PlayStation pads stream continuously; Xbox pads only report on change, so keep a stick moving.

Input lag uses Intel PresentMon (ETW, the same data PresentMon/CapFrameX use). It matches each mouse/keyboard input event the OS sees to the first frame that reaches the display afterwards: input → photon. The tester adds the average poll wait (half the poll interval) for an estimated end-to-end number. Not included: sensor/switch debounce inside the device and the panel's pixel response. Those need a hardware photodiode tester (LDAT, OSLTT…).

Controllers aren't visible to the OS input stack, so for them the chain is an estimate: poll wait + ½ frame (the game samples input once per frame) + frame → photon.

Controller Lab reads the actual stick values from the HID report: drift test (resting offset, noise, max deviation, suggested deadzone) and circularity (outer-edge error, like hardwaretester.com/gamepad). Decoding only runs while the lab is visible or a test is running.

Low overhead by design

  • Only the selected input class is registered. The collector thread only timestamps and copies.
  • Stats run 4× a second on a below-normal priority thread, with fixed-size histograms.
  • Opted out of Windows EcoQoS throttling so timestamps stay accurate while the game is in front.
  • This page pauses its stream when hidden. Keep it on a second monitor or open it on your phone with --lan.

Hotkey

Ctrl+Shift+F9 starts/stops a session from inside a game. Sessions are saved as JSON in the sessions folder.
